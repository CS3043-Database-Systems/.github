## 📌 About This Organization

This GitHub organization contains the repositories created throughout the **CS3043 Database Systems** module.

It is not limited to lecture notes. Separate repositories will be maintained for different parts of the module, including:

- Weekly learning notes
- Lecture and tutorial materials
- Laboratory work
- SQL exercises
- Database design activities
- ER diagrams and relational schemas
- Assignments
- Individual and group projects
- Practical implementations
- Revision resources
- Exam preparation
- Additional experiments and research

The main goal is to create a structured, version-controlled knowledge base that documents both the theoretical and practical sides of database systems.

---

## 🎯 Objectives

This organization is designed to:

- Organize all module-related work in one place
- Track learning progress throughout the semester
- Connect database theory with practical implementations
- Practise database design and SQL development
- Maintain clean documentation for future revision
- Support assignments, laboratory work, and projects
- Build reusable academic and technical resources
- Develop good Git, GitHub, and software engineering practices

## 🗂️ Repository Structure

Each major area of the module will be maintained in a separate repository.

| Repository | Purpose |
|---|---|
| `CS3043-Weekly-Notes` | Weekly notes created and organized through Notion |
| `CS3043-SQL-Practice` | SQL queries, exercises, examples, and solutions |
| `CS3043-Labs` | Laboratory activities and practical implementations |
| `CS3043-Assignments` | Module assignments and related documentation |
| `CS3043-Database-Design` | ER diagrams, schemas, normalization, and design exercises |
| `CS3043-Projects` | Individual or group database-related projects |
| `CS3043-Revision` | Summaries, cheat sheets, active-recall questions, and exam preparation |

Repository names and structures may change as the module progresses.

## 📝 Weekly Notes Workflow

Weekly learning notes are initially organized in **Notion** and then maintained in GitHub for long-term storage, version control, and accessibility.

Each week may include:

1. Lecture concepts
2. Simplified explanations
3. Important definitions
4. Diagrams and database models
5. SQL examples
6. Laboratory work
7. Questions and answers
8. Common mistakes
9. Additional research
10. Weekly summaries
11. Active-recall questions
12. Revision checkpoints

This process allows the notes to improve continuously rather than remaining as static lecture summaries.
